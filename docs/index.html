01

简介

g1_barcode_sim 是一个基于 Isaac Sim 5.1 / Isaac Lab 的仿真环境，用来开发和评测人形机器人的"找码—接近—扫码"能力。场景里有一台 Unitree G1，左手的 Dex1 夹爪握着一把手持扫码枪；纸箱放在桌上、货架上或直接堆在地上，箱面贴着 Code128 或 QR 条码标签。使用者通过 Python 接口控制机器人行走、下蹲、移动手臂和瞄准，再"扣扳机"扫码，环境返回对枪头相机画面的真实解码结果。

环境本身不包含找码、导航或扫码策略；它提供传感器、控制接口、可复现的场景和仅供评测用的 ground truth（GT）。

02

环境配置

本仓库运行在 Isaac Sim 5.1 + Isaac Lab 之上，并在运行时复用 unitree_sim_isaaclab 的 G1 模型和任务模板，所以需要完整安装这三者。下面的步骤按依赖顺序排列；所有第三方仓库都固定到经过测试的 commit。

硬件与系统要求

  • 一台满足 Isaac Sim 5.1 官方硬件要求、带 NVIDIA GPU 的 Linux 机器。单个场景约占 5 GB 显存。
  • 已安装 conda、git、git-lfs、cmake、C/C++ 编译工具链（如 build-essential）和 unzip。
  • 预留数十 GB 磁盘空间：Isaac Sim 的 pip 包与扩展缓存较大，unitree_sim_isaaclab 的 USD 资产下载约 1.2 GB、解压后约 1.7 GB。
  • 能访问 NVIDIA 的在线 Isaac 资产库：默认场景从那里加载仓库背景和纸箱模型（离线方案见常见问题）。
  • 物理仿真跑在 CPU 上（与上游一致），渲染使用 GPU。

安装步骤

建议把本仓库和 unitree_sim_isaaclab 放在同一个父目录下。这样不需要设置 UNITREE_SIM_ROOT，代码默认就在本仓库旁边找上游仓库：

workspace/
├── IsaacLab/                 第 3 步
├── cyclonedds/               第 4 步
├── unitree_sdk2_python/      第 4 步
├── unitree_sim_isaaclab/     第 5 步（默认位置：本仓库的同级目录）
└── g1_barcode_sim/           本仓库
  1. 创建 conda 环境（Python 3.11）

    Isaac Sim 5.1 的 pip 包只支持 Python 3.11。

    conda create -y -n g1sim python=3.11
conda activate g1sim
python -m pip install --upgrade pip
  2. 安装 Isaac Sim 5.1.0

    详见 Isaac Sim 官方的 pip 安装文档。首次运行要接受 EULA；之后可以用环境变量 OMNI_KIT_ACCEPT_EULA=YES 跳过交互。

    pip install "isaacsim[all,extscache]==5.1.0" --extra-index-url https://pypi.nvidia.com
export OMNI_KIT_ACCEPT_EULA=YES
isaacsim            # 可选：首次启动一次，确认能打开（会下载并缓存扩展）
  3. 安装 Isaac Lab（固定 commit）

    使用 unitree_sim_isaaclab 文档指定的 commit（v2.3.2 之后 7 个提交）。安装脚本会同时装好 torch（2.7.0+cu128）。

    git clone https://github.com/isaac-sim/IsaacLab.git
cd IsaacLab
git checkout 80094be3245aa5c8376a7464d29cb4412ea518f5
./isaaclab.sh --install
cd ..
  4. 编译 CycloneDDS 0.10.x，安装 unitree_sdk2_python

    本仿真不走 DDS 通信，但上游模块在 import 时会加载 unitree_sdk2py 和 cyclonedds，所以必须安装。

    git clone https://github.com/eclipse-cyclonedds/cyclonedds -b releases/0.10.x
cd cyclonedds && mkdir -p build install && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=../install && cmake --build . --target install
cd ../..
export CYCLONEDDS_HOME=$PWD/cyclonedds/install

git clone https://github.com/unitreerobotics/unitree_sdk2_python
cd unitree_sdk2_python
git checkout 814556d15970dd2ecf1c9984e845ca02ab07e206
pip install -e .
cd ..
  5. 安装 unitree_sim_isaaclab（固定 commit）并下载 USD 资产

    fetch_assets.sh 从 HuggingFace 数据集 unitreerobotics/unitree_sim_isaaclab_usds 下载机器人模型等资产，需要 git-lfs。本仿真不需要上游的 teleimager 子模块（只有上游自己的 sim_main.py 和 XR 遥操作会用到）。

    git clone https://github.com/unitreerobotics/unitree_sim_isaaclab.git
cd unitree_sim_isaaclab
git checkout e30c25b1dffdf92ada1d6c8c1fe9a47bdde0fecc
pip install -r requirements.txt
bash fetch_assets.sh             # 生成 assets/robots、assets/model 等
cd ..
  6. 安装本仓库的额外依赖

    pyzbar 需要 zbar 共享库（这里用 conda-forge 的包，也可以用系统包 libzbar0）。pyarrow 的版本锁定见常见问题。条码标签上的可读文字优先使用 DejaVu 字体（如系统包 fonts-dejavu），没有时回退到 Pillow 默认字体，不影响条码本身。

    conda install -y -c conda-forge zbar libstdcxx-ng
pip install python-barcode==0.16.1 qrcode==7.4.2 pyzbar==0.1.9 \
            pillow opencv-python pyyaml scipy imageio-ffmpeg pytest
pip install --no-deps "pyarrow==23.0.1"
  7. 克隆本仓库，设置环境变量 
    git clone <本仓库地址> g1_barcode_sim
cd g1_barcode_sim
export OMNI_KIT_ACCEPT_EULA=YES
# 只有 unitree_sim_isaaclab 不在 ../unitree_sim_isaaclab 时才需要：
export UNITREE_SIM_ROOT=/path/to/unitree_sim_isaaclab
  8. 生成条码贴图（可选）

    环境首次启动时会自动生成缺失的贴图并逐张解码校验；也可以提前批量生成：

    python scripts/generate_barcodes.py              # Code128，退出码 0 表示全部解码正确
python scripts/generate_barcodes.py --type qr

03

仿真实现细节

环境以上游任务 Isaac-Move-Cylinder-G129-Dex1-Wholebody 为模板：启动时复制它的配置，删掉上游的房间、桌子、圆柱和相机，再加入本项目的场景、相机、扫码枪和控制器。上游文件本身不做修改。默认参数集中在 configs/ 下的 YAML 里，构造环境时也可以用 config_overrides 覆盖。

3.1 机器人与末端

  • 型号：Unitree G1，本体 29 个自由度（每条腿 6、腰 3、每条手臂 7）；两只手各一个 Unitree Dex1 两指平行夹爪，每个夹爪 2 个棱柱关节；整机 33 个关节。
  • 模型来源：unitree_sim_isaaclab 的 assets/robots/g1-29dof_wholebody_dex1/g1_29dof_with_dex1_rev_1_0.usd（配置 G129_CFG_WITH_DEX1_WHOLEBODY），运行时从上游仓库读取。不开启自碰撞。
  • 末端执行器：configs/robot.yaml: end_effector 目前只接通了 dex1，选 dex3 或 inspire 会抛出 NotImplementedError。
  • 夹爪：关节目标张开 −0.02、闭合 0.024（Isaac Lab 关节值）。API 的开度 opening ∈ [0, 1]（0 闭合、1 张开）线性映射到这两个值。执行器沿用上游 implicit PD。
  • 左手持枪：扫码枪刚性挂在左手 left_hand_base_link 下的 scanner_mount 节点上，握持点在两指垫中间。启动时根据指垫碰撞体的实时位置算出"两侧指垫正好贴住 3.0 cm 宽枪柄"的关节目标，reset 时直接写入，不需要重新夹取。持枪的左手不响应夹爪指令：set_gripper("left", …) 返回 error，set_gripper("both", …) 只作用于右手。
  • 不装枪：configs/scanner.yaml: enabled: false，或构造时传 config_overrides={"scanner": {"enabled": False}}。这时左夹爪恢复可控，不创建枪头相机，scan() 和 aim_scanner() 返回 error。

3.2 全身控制与行走

GR00T Decoupled WBC（默认）

下肢和腰部由 NVIDIA GR00T Decoupled WBC 的两个 ONNX 策略控制：Balance（站立）和 Walk（行走），文件在 assets/gear_wbc/，来自 NVlabs/GR00T-WholeBodyControl，未做修改。策略在 CPU 上用 onnxruntime 推理。

  • 切换：速度命令的模长 ‖(vx, vy, wz)‖ < 0.05 时用 Balance，否则用 Walk，自动切换；两个网络共用同一份观测历史和上一步动作。
  • 频率：物理步长 0.005 s（200 Hz）；decimation 4，策略、手臂 IK 和相机渲染都是 50 Hz（env.policy_dt = 0.02）。启动时检查物理步长与 GR00T 参考配置一致。
  • 输出：[1, 15]，12 个腿关节 + 3 个腰关节的位置目标：目标 = 输出 × 0.25 + 默认角。默认角为髋 pitch −0.1、膝 0.3、踝 pitch −0.2，其余 0 rad。
  • 执行器：这 15 个关节用一组显式 PD（IdealPD），kp/kd 取自 GR00T 参考配置：髋 150/2、膝 200/4、踝 40/2、腰 250/5。力矩上限（N·m）：髋 88、膝 139、踝 50、腰 yaw 88 / roll 50 / pitch 50。

输入为 [1, 516]：最近 6 帧观测，每帧 86 维，从旧到新排列，reset 后用零帧补齐。每帧的组成：

分量维数缩放
速度命令 (vx, vy, wz)3× [2, 2, 0.5]
身体高度命令1原值
躯干 roll / pitch / yaw 命令3原值

底盘移动

  • step(vx, vy, wz, duration)：以 root（骨盆）坐标系下的速度走 duration 秒，结束后速度命令清零。命令先截断到 |vx| ≤ 0.4 m/s、|vy| ≤ 0.5 m/s、|wz| ≤ 1.0 rad/s。每个策略步检查一次状态，摔倒或碰撞时提前结束。命令在进程内一直保持，不像上游 DDS 接口那样读一次就清零。
  • stand_still(duration)：等于 step(0, 0, 0, duration)。
  • move_relative(dx, dy, dyaw, timeout=10.0, pos_tol=None, yaw_tol=None, speed_scale=1.0)：基于里程计的闭环移动，目标在起始 root 坐标系下给出。控制律是饱和 P 控制：误差大于制动距离（0.15 m / 0.30 rad）时用满限幅，之内线性减速；某一轴误差还在容差外时，命令不低于最小值（vx 0.15、vy 0.3、wz 0.6），避免低速时走不动。每轮结束先停稳（速度 < 0.03 m/s 持续 0.3 s，最多等 3 s）再复查误差，最多 3 轮。默认容差 3 cm / 0.03 rad。
  • 里程计：T_world_root_odom 不是状态估计器的输出，而是在真值上叠加确定性漂移：每米 ±2% 位移误差、每米 ±1° 航向误差，正负号由 reset 的 seed 决定；roll / pitch 用真值。
  • 状态判定：躯干倾斜超过 45° 判为 fell；机器人碰撞体（含扫码枪外形）的任一顶点进入家具或纸箱时判为 collision。collision 只是状态报告，不会阻止物理接触；间隙只按顶点计算，是上界。

3.3 手臂控制

手臂不受行走策略控制。每只手臂 7 个关节，由 IK 或关节指令直接给出位置目标，再由上游的 implicit PD 执行器跟踪。每个策略步（50 Hz）先根据当前实测关节状态更新一次 IK，再运行一次行走策略，所以 IK 是逐步闭环的。

  1. 手腕位置：set_wrist_target(side, pos_root)、move_wrist(side, dx, dy, dz)。阻尼最小二乘微分 IK，只控制 {side}_hand_base_link（夹爪基座）在 root 坐标系下的位置，不控制姿态。每步 dq = gain·Jᵀ(JJᵀ + λ²I)⁻¹e，gain 0.1、λ 0.05，雅可比来自 PhysX。目标被限制在默认手腕位置 ±0.25 m 的框内；够不到时停在最近的可达点。
  2. 扫码枪瞄准（左臂）：aim_scanner(tip_pos_root, dir_root, anchor="odom")、aim_scanner_at(point_root, normal_root, distance=0.20, anchor="odom")。5 维任务：枪口位置 3 维 + 扫描方向 2 维，不约束绕扫描轴的滚转；方向误差乘以 0.20 m/rad（标称扫描距离）与位置误差加权。anchor="odom" 时目标固定在里程计坐标系中，底盘漂移会被逐步补偿；"root" 时目标随身体移动。瞄准模式不受手腕框限制，残差在 obs["scanner_aim_error"] 中报告。
  3. 关节空间：env.arm.set_joint_targets(side, q, n_steps)，在 n_steps 个策略步内从当前指令线性插值到 7 维关节目标 q。env 上没有对应的封装方法。

通用限制：每步关节变化不超过 0.05 rad（即 2.5 rad/s），并夹到关节软限位内。reset_arms() 清除目标，双臂回到默认姿态（肩 pitch 0.35、肩 roll ±0.18、肘 0.87 rad，双手在髋部前方，手腕约在 root 系 (0.0, ±0.22, −0.09) m）。

  2. 结果完全来自图像解码：没有任何距离、角度或视场阈值。对不准、太近（标签出画）、太远（模块太小）、入射太斜、遮挡，都会自然导致解码失败。

  4. 选码：同一内容只保留一次；画面里有多个码时，content 取离画面中心最近的那个，模拟真机的瞄准点。
  5. GT 诊断：额外把扫描射线（tip 的 x 轴）与所有 GT 标签矩形求交，只计从正面入射的命中，给出命中的标签、距离和入射角。只用于评测和排查失败原因，不考虑遮挡，也不影响 status。

标签几何

标签是箱子 prim 的子节点，随箱子移动。它由一个带贴图的四边形（单面）和可选的白色底板组成：

  • 底板（backing）：白色薄片，厚 1 mm（barcode.yaml: label_thickness）。内置场景总是带底板，标签外形为 Code128 10 × 5 cm、QR 6 × 6 cm（含静区），条码图案最大 8 × 3 cm / 5 × 5 cm。测试场景由 label_backing 决定：有底板时标签 = 图案 + 每边 1 cm 白边；无底板时图案的浅色模块直接用箱面颜色，相当于印在箱子上。
  • face_offset：标签正面离箱面 1.5 mm，避免 z-fighting。
  • 放置参数：u、v 从面中心量起（米），u 沿该面的"右"方向，v 向上；rot_deg 为面内旋转，从箱外看逆时针为正。
  • 材质：roughness 0.8、metallic 0；带语义标签 class=barcode（箱子 class=box，家具 class=table / shelf），可用于生成分割真值。

Task suites（测试场景集）

Task suite 是一组可复现的测试场景，每个场景由一个 JSON 文件完整描述，用 env.reset(scenario=...) 加载，同一进程内可以连续切换。目前有两类：桌面场景（t1_*、t2_*，共 18 套，由生成器按因素表产出）和箱堆场景（stack*，共 6 套，手写）。Suite 会持续扩充，新的场景类型和难度等级会陆续加入。

注意场景 JSON 里只描述场景本身，不含 GT 目标；GT 在 reset 之后由 get_ground_truth() 计算，只用于评测。

可复现性：每个场景的随机数流由 SHA-256(套件名|seed|序号|尝试次数) 派生，与 Python 哈希种子和生成顺序无关；每个套件在内存中生成两次，逐字节一致才写盘；manifest 不含时间戳，code_hash 记录生成器源码和配置的哈希。

已知限制与许可证

已知限制

  • 行走：低速时后退、横移和转向的跟踪不足（只完成命令位移的 30–70%），左转与右转响应不对称；从 0.4 m/s 停下后底盘还会滑行约 10–15 cm；左臂抬起行走时航向会向右偏 2–4.5°。move_relative 的闭环和多轮复查可以弥补大部分误差。
  • 下蹲：高度命令下限 0.20 m 没有实测过，实测最低到 0.25 m（骨盆约 0.25 m）。
  • 里程计不是估计器，而是真值加确定性漂移（每米 2% / 1°）。
  • 相机：头部相机参数取自上游仿真配置（水平视场 105.5°，比真机 D435i 宽），枪头相机按 DS2208 规格估算，两者都没有与真机标定。
  • 扫码：scan() 是对渲染画面的图像解码，没有模拟真机的解码距离和角度规格；默认只解码原图，条码长轴需与画面横轴大致对齐（约 ±17° 以内）。
  • 扫码枪只有外观，没有质量和碰撞体，手臂负载比真机（约 160 g）轻；与场景的接触只在间隙检测中体现。
  • 碰撞：机器人不开启自碰撞；摔倒只按倾斜角判定；间隙只按顶点计算（上界）。仓库背景只作外观，碰撞已关闭。
  • 末端只接通了 Dex1；手腕 IK 只控制位置。
  • 标签：GT 只支持四个竖直面（顶面 +z 没有水平站位方向）；内置场景 GT 的 pattern_size 为 null。
  • 运行：物理在 CPU 上运行，每个策略步渲染头部、枪头和辅助相机，仿真速度明显低于实时（取决于硬件）；一个进程只能创建一个环境，close() 结束进程；场景依赖在线 Isaac 资产（可改用几何体）。
